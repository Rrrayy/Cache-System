# RArcCache

基于 ARC 幽灵反馈思想实现的线程安全 LRU/LFU 自适应混合缓存。

> 本实现使用显式 LFU 频次管理，并非论文 ARC 的严格复刻。

## 设计结构

```text
RArcCache
├── ArcLruPart：保存近期访问数据
│   └── LRU Ghost：记录被淘汰的key
└── ArcLfuPart：保存高频访问数据
    └── LFU Ghost：记录被淘汰的key
```

- 新数据首先进入 LRU。
- LRU 中的节点达到访问门槛后迁移到 LFU。
- LRU 根据最近访问顺序淘汰。
- LFU 根据访问频次淘汰，同频次时淘汰最早进入频次链表的节点。
- 同一个 key 只存在于一个真实缓存分区。
- LRU 与 LFU 的容量之和始终等于总容量。

## 自适应机制

幽灵缓存只记录被淘汰的 key，不保存 value，用于判断近期淘汰是否合理。

```text
命中LRU幽灵缓存
→ 说明近期访问数据需要更多空间
→ 扩大LRU，缩小LFU

命中LFU幽灵缓存
→ 说明高频数据需要更多空间
→ 扩大LFU，缩小LRU
```

每次调整一个缓存槽位，使缓存能够随访问模式变化，在最近性和访问频率之间动态平衡。

## 访问流程

### 写入

```text
检查幽灵缓存
→ 调整分区容量
→ key已在LFU：更新LFU
→ 否则写入LRU
→ 分区满时执行对应淘汰
```

### 查询

```text
先查询LRU
→ 命中后更新最近位置和访问次数
→ 达到门槛后迁移到LFU
→ LRU未命中则查询LFU
→ LFU命中后提升访问频次
```

## 数据结构

### LRU

```text
unordered_map：平均O(1)定位节点
双向链表：维护最近访问顺序
```

链表头部为最近访问节点，尾部为最久未访问节点。

### LFU

```text
unordered_map：key到节点
map：访问频次到节点链表
迭代器索引：快速迁移节点
```

优先淘汰最低频次节点；频次相同时按 LRU 顺序淘汰。

## 线程安全

顶层互斥锁保护：

- 幽灵缓存检查
- 分区容量调整
- LRU 到 LFU 的迁移

LRU 和 LFU 分区分别使用互斥锁保护内部哈希表和链表。

当前采用粗粒度锁优先保证正确性，后续可通过分片缓存降低高并发下的锁竞争。

## 复杂度

| 操作 | 平均复杂度 |
|---|---:|
| LRU 查询、写入、淘汰 | `O(1)` |
| LFU 查询、写入、淘汰 | `O(log F)` |
| 幽灵缓存查询、淘汰 | `O(1)` |
| 空间复杂度 | `O(N)` |

`F` 表示当前不同访问频次的数量。LFU 使用 `std::map` 管理频次，因此不是严格 `O(1)`。

## 与标准 ARC 的区别

标准 ARC 使用 `T1/T2/B1/B2` 四条 LRU 链表和参数 `p` 调整容量。

本实现保留了：

- 双真实缓存区域
- 双幽灵缓存
- 根据幽灵命中动态调整容量

同时将高频区域改为显式 LFU，并通过访问门槛控制晋升。因此更准确的定位是：

> 基于 ARC 思想的 LRU/LFU 自适应混合缓存。
